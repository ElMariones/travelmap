## 1. What the app is

Log the countries you've been to; watch your world fill in with colour. The design goal
is that logging a place takes under ten seconds and is never more than two taps away.
Everything else — stats, regions, friends — supports that loop rather than competing
with it.

The map is the hero. Stats and profile are secondary tabs.

## 5. Data flow

```
Supabase ──► AuthService ──► SessionStore ──► (userID)
                                               │
countries.geojson ─┐                           │
regions.geojson ───┴─► GeoDataService ──► VisitStore ◄── VisitsService ───────► Supabase
                                               ▲
                                               └──── RegionVisitsService ────► Supabase
                                               │
              WorldMapScreen · Country/Region detail · Visits · Stats · Profile
                                               │
                                     TravelSnapshotStore
                                       (App Group)
                                               │
                            TravelMapWidgets ──┴──► WorldProgressView
```

`VisitStore` is the only thing views read visit data from. **Percentages are always
derived, never stored** — country and region progress compare the bundled reference sets
against distinct visited codes, so there is no counter that can drift. A regional visit
also fills its parent country; deleting the last country and regional visit grays it out.

The widget is a second process with no Supabase session, so it can't derive anything: it
reads the counts the app already computed. `publishSnapshot()` runs on every path that
changes the visited set (load, save, delete, sign-out) and is the *only* writer. A test
asserts the widget's percentage string matches the app's for the same numbers, because
two code paths rendering one figure is exactly how a home screen ends up contradicting
the app it belongs to.

Celebrations funnel through `CelebrationCenter` for the same reason: when a store and a
view both react to one save, the user gets two haptics and two overlapping animations.
`VisitStore.addVisit` *reports* what changed via `SaveOutcome`; it fires nothing itself.
Regional saves use the same ownership boundary: the store changes data, while the form
chooses the semantic haptic for a repeated visit versus a newly filled region.

## 6. The map

`CountryMapView` wraps `MKMapView` directly rather than using SwiftUI's `Map`, because
the fill-in effect needs `MKMultiPolygonRenderer`: one country can be recoloured in place
without rebuilding the other 235.

- One `MKMultiPolygon` overlay per country, added at `.aboveRoads` so system labels stay
  on top. The ISO code rides on the overlay's `title`.
- `applyVisitedCodes` diffs the set and only repaints what changed.
- Tap handling does its own ray-casting (`MKPolygon.contains`) in projected map space
  with a bounding-box prefilter, rather than relying on renderer paths that may not exist
  yet. Overlapping bounding boxes resolve to the tightest match.
- The base map is `MKStandardMapConfiguration(elevationStyle: .flat, emphasisStyle:
  .muted)` with POIs excluded, so the overlays carry all the meaning.
- The camera settles onto the user's own countries once, shortly after launch, as soon as
  visits arrive. Before that it can only show the default world framing, because visits
  load after the map does. A spread wider than 60% of the world falls back to that
  framing rather than computing a rect — one visit to Fiji and one to Chile span the
  planet the long way round.

### The regional map

`RegionMapView` uses the same overlay and hit-testing approach, but installs only the
selected country's shapes. `RegionMapData` decodes the 4,477-feature file once, indexes
it by country and code, and supplies bounds and hit testing. Countries with fewer than
two shapes skip regional mode automatically. The percentage stays hidden until at least
one subdivision is logged, then appears in country detail and Stats.

### The widget's second copy

A widget extension cannot use MapKit, so it draws its own. `scripts/build-widgetmap.mjs`
reads the *already bundled* `countries.geojson` — no network, no mapshaper — projects it
equirectangularly, cropped to 56°S–83°N, simplifies with Ramer–Douglas–Peucker, and writes
integer coordinates on a proportional grid. 41 KB, ~3,600 points, two `Path`s at draw time
rather than 236.

Forty micro-states simplify away to nothing at that scale. They get a small diamond at
their centroid instead of being dropped, so somebody whose only visit is Singapore doesn't
look at an entirely empty map. A test asserts every country in the reference set is
drawable.

## 7. Data model and security

Five tables, all with RLS enabled: `profiles`, `visits`, `region_visits`, `friendships`,
`comments`. Full definitions in `supabase/schema.sql`.

`visits.visited_at` remains a Postgres `date` for sorting, but new records only store the
first day of the selected year/month and carry `date_precision = year|month`. Existing V1
exact dates have no precision and remain readable. `title` is nullable in SQL solely so
existing rows migrate safely; new and edited visits require one in the app.

- A Postgres trigger on `auth.users` creates the profile and its friend code, so the
  client never sees a user without one.
- `are_friends(a, b)` is `SECURITY DEFINER` — the visits policies call it, and without
  that it would re-enter the friendships policies and recurse.
- Photos live in a **private** bucket. `visits.photo_urls` holds Storage *object paths*,
  not URLs; the app makes signed URLs at display time.
- `delete_account()` is `SECURITY DEFINER` and reads `auth.uid()` internally, so a caller
  can only ever delete themselves.

## 8. Design system

`AppTheme.swift` is the normative source. Summary:

**Liquid Glass**

- Glass is the **control layer**. It floats above content and is never a content
  background.
- **Never nested.** Sheets, the tab bar and navigation bars are already system glass, so
  nothing inside them gets `.glassEffect`. Siblings inside a `GlassEffectContainer` are
  fine and are how shapes blend into each other.
- **`.regular`** is the only safe choice over unpredictable content — the map, where the
  user may be over pale ocean or dark terrain. It brings its own legibility handling.
- **`.clear`** does not. It is used exactly once, on the landing screen, over a gradient
  the app draws *and dims itself*. That dimming is the precondition; without it, clear
  glass is not allowed.
- Tint is reserved for the single primary action so it keeps meaning something.

**Motion**

- Springs, not durations. A spring absorbs a new target mid-flight, which is what makes a
  re-tap during an animation feel answered rather than queued.
- `AppTheme.Motion`: `snappy` (state flips), `bouncy` (things appearing), `gentle`
  (ambient), `morph` (glass shapes).
- Zoom transitions on the add-visit paths. They stay interruptible — do not add
  `interactiveDismissDisabled` except while a save is genuinely in flight.
- **Everything large-scale is gated on Reduce Motion**, with a static equivalent that
  carries the same information: the aurora freezes rather than flattening, the landing
  mark stops drifting, the headline number stops popping, and the confetti simply doesn't
  emit — the celebration card says the same thing without it.

**Feedback**

Three channels, and each event uses the ones its audience can perceive. This is a
single-user app held in one hand, so haptics reach as far as anything.

| Event | Motion | Haptic | Overlay |
| --- | --- | --- | --- |
| Chip, row, copy | — | `.selection` | — |
| Visit saved to a known country | map badge bounce | `.visitLogged` | — |
| Visit fills a **new** country | country recolours, badge bounce | `.newCountry` | — |
| Milestone crossed | confetti | `.milestone` | card |
| Account created | confetti | `.welcome` | card |
| Visit removed | country may gray out | `.removed` | — |
| Anything failed | error text | `.failure` | — |

The gradient is deliberate: the rarest events get the biggest patterns, and only the two
rarest get the screen. `HapticEvent` names *meanings*, never waveforms, so the patterns
can be retuned on a device without touching a call site. Core Haptics obeys no system
setting, so Profile carries the off switch.

## 9. Hard-won constraints

Things that cost real debugging time. Do not re-derive these.

| Constraint | Detail |
| --- | --- |
| **MapKit can't show the whole world** | A flat map's camera hard-clamps at ~38,500 km out, about 95° of longitude on a portrait phone. Asking for more returns the same clamped result, in both elevation styles. The "All" chip gives MapKit's widest framing. |
| **Camera needs real bounds** | `setVisibleMapRect` in `makeUIView` runs before the view has a size. `LayoutReportingMapView` reports first layout; frame the camera there. |
| **Folder references don't flatten** | `MapData` is a folder reference, so `Bundle.url(forResource:withExtension:)` returns `nil`. Pass `subdirectory: "MapData"`. |
| **xcconfig eats `//`** | Even mid-value. `$()` no longer survives Info.plist preprocessing. Only `$(SLASH)$(SLASH)` works — verified against `-showBuildSettings`. |
| **UUID case mismatch** | Swift's `UUID.uuidString` is uppercase; Postgres `auth.uid()::text` is lowercase. Storage paths must be lowercased, or uploads fail as "violates row-level security policy" far from the cause. |
| **Two `.sheet`s on one view** | SwiftUI silently leaves one unable to present. Drive multiple sheets from one modifier and an enum. |
| **Field padding isn't tappable** | A `TextField`'s hit area is its glyphs. A tap-to-focus gesture fixes it, but must sit **behind** the field — in front it beats the field's own recognisers and swallows long-press select/paste. |
| **`.breathe` washes out** | It dips a symbol's opacity far enough that a brand mark visibly fades. Don't use it on the logo. |
| **Simulator strips the Apple entitlement** | Ad-hoc signing drops `com.apple.developer.applesignin`. Sign in with Apple cannot complete in the simulator without a real team. |
| **Text injection ignores layout and shift** | On a non-US Mac layout, injected `-` and `@` come out wrong, and capitals may be lost. For simulator UI testing, prefer credentials that are lowercase and punctuation-free. |
| **Icon Composer groups run front to back** | `groups[0]` is the *topmost* layer, not the bottom one. Getting it backwards paints the opaque globe over everything and produces a plain white disc — with no error. |
| **Its SVG renderer ignores `stroke`** | Only fills are drawn. Outline every stroke by hand. A stroked layer compiles cleanly and renders as nothing. |
| **And its arc support is unreliable** | An `A`/`a` elliptical arc came out as a pie wedge. `scripts/build-icon.mjs` emits every curve as an explicit polygon — `M`, `L`, `Z` only. |
| **`shadow.kind` accepts only `neutral` and `none`** | Anything else fails the build with `Exception while running actool: attempt to insert nil object`, naming neither the file nor the key. |
| **SpringBoard caches app icons hard** | Reinstalling is not enough to see a new icon. Uninstall, `simctl shutdown`, `boot`, reinstall — otherwise you spend an hour debugging the render you already fixed. |
| **`CAEmitterLayer` copies its cells** | Assigning `emitterCells` hands the layer its own copies; mutating the originals afterwards writes to objects it no longer uses. The symptom is a burst that fires, reports nothing, and emits nothing. Rebuild and reassign the cells on each burst. |
| **A `UIViewRepresentable` created by the event it renders never sees a trigger change** | The celebration overlay appears *with* the new value already set. Leave the coordinator's last-seen value `nil` so the first `updateUIView` counts as a change, and defer the burst until the view has bounds. |

## 11. Running on a device

The Simulator needs nothing. A real iPhone needs a signing identity. Sign in with Apple
is the only requested capability a free personal team cannot grant; App Groups and the
widget work. That distinction is the whole difficulty, so it comes first.

### What each account type can actually run

| | Free Apple ID (personal team) | Apple Developer Program ($99/yr) |
| --- | --- | --- |
| Map, stats, photos, celebrations, haptics | ✅ | ✅ |
| Email + password sign-in | ✅ | ✅ |
| **App Groups** → the widget's data | ✅ | ✅ |
| Widget, with real data | ✅ | ✅ |
| **Sign in with Apple** | ❌ | ✅ |
| Build expires | after **7 days** | after 1 year |
| Devices | 3 apps at a time, 10 app IDs a week | 100 devices |

**Only Sign in with Apple is actually blocked.** Xcode says so precisely — *"Personal
development teams … do not support the Sign In with Apple capability"* — and then can't
issue a certificate at all until the entitlement is removed.

App Groups **are** granted to a personal team; this was verified by building for a device
on one and reading the signed entitlements back:

```
"application-identifier" => "MA7W7A6S66.com.mariolandaburu.travelmap"
"com.apple.security.application-groups" => [ 0 => "group.com.mariolandaburu.travelmap" ]
```

So a free account runs everything here except Sign in with Apple, widget included. (AltStore
is sideloaded the same way and uses app groups; its `group.…AltStore.<TEAMID>` naming is a
collision-avoidance convention, not a requirement.)

### The four settings

All in `project.yml` under `settings.base`, and everything else derives from them — the
widget and test bundle ids, both entitlements files, both Info.plists, the app group
`TravelSnapshotStore` reads back at runtime, and whether the landing screen offers Sign in
with Apple at all.

```yaml
DEVELOPMENT_TEAM: MA7W7A6S66                        # your ten-character Team ID
SUPPORTS_SIGN_IN_WITH_APPLE: NO                     # YES needs a paid membership
APP_BUNDLE_ID: com.mariolandaburu.travelmap         # must be globally unique
APP_GROUP_ID: group.com.mariolandaburu.travelmap    # must start with "group."
```

Then `xcodegen generate`. The identifiers used to be spelled out in six places; a
disagreement between any two of them broke the widget silently.

### Turning Sign in with Apple off (free team) and back on (paid)

Two things move together, and either one alone is broken:

1. `SUPPORTS_SIGN_IN_WITH_APPLE` in `settings.base`.
2. The `com.apple.developer.applesignin` block in the `TravelMap` target's `entitlements`
   properties, which is currently commented out.

Nothing else changes. `AppleSignIn.isAvailable` reads the flag out of Info.plist and
`LandingView` omits the button entirely, promoting "Continue with email" to the prominent
style so the screen doesn't look like something failed to load. Leaving the button in
place instead would open the system sheet and fail — which reads as a broken app rather
than as a capability this build doesn't have.

### Install from the command line

Xcode's Run button does all of this, but the CLI path is scriptable and says what failed.

```bash
# 1. Which device — the Identifier column is a CoreDevice UUID
xcrun devicectl list devices
DEV=<identifier>

# 2. Build signed. Note `generic/platform=iOS`: xcodebuild matches on the *hardware*
#    UDID, not the devicectl identifier, so passing $DEV here fails to find any device.
xcodebuild build -project TravelMap.xcodeproj -scheme TravelMap \
  -destination 'generic/platform=iOS' -allowProvisioningUpdates

# 3. Resolve the built app — device builds land in Debug-iphoneos, not -iphonesimulator
eval $(xcodebuild -project TravelMap.xcodeproj -scheme TravelMap \
  -destination 'generic/platform=iOS' -showBuildSettings 2>/dev/null \
  | awk -F' = ' '/ TARGET_BUILD_DIR =/{print "DIR=\""$2"\""} / FULL_PRODUCT_NAME =/{print "NAME=\""$2"\""}')

# 4. Install and launch
xcrun devicectl device install app --device "$DEV" "$DIR/$NAME"
xcrun devicectl device process launch --device "$DEV" "$(/usr/libexec/PlistBuddy \
  -c 'Print :CFBundleIdentifier' "$DIR/$NAME/Info.plist")"
```

One-time, on the phone itself, and not scriptable: **Developer Mode** on (Settings ▸
Privacy & Security ▸ Developer Mode, then restart), and **Trust This Computer** on first
USB connection. The signing Apple ID must be logged into Xcode ▸ Settings ▸ Accounts
before `-allowProvisioningUpdates` can mint anything.

**The phone must be unlocked and awake for the install.** A locked or sleeping device
shows as `unavailable` in `devicectl list devices` and the install command simply hangs
until it times out, with no message saying why. Check the State column first; wake the
phone and it goes back to `connected`.

### Device-only things worth checking once you're there

- **Haptics.** The Simulator plays none, so every intensity and sharpness in
  `Haptics.swift` is an untuned first guess. This is the main reason to get onto hardware.
- **Sign in with Apple** — but only on a paid account. It cannot complete in the Simulator
  either, since ad-hoc signing strips the entitlement. It also needs Supabase's Apple
  provider enabled, with the bundle id as an authorized client.
- **The widget**, added to the Home Screen and the Lock Screen for real. The debug harness
  checks layout, not the tile material or the Lock Screen's monochrome rendering.
- **The icon** on a real wallpaper, in light, dark and tinted.
